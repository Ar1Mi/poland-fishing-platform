# Новый ADR

Тема: `$ARGUMENTS`

1. Прочитай `docs/adr/README.md` и `docs/adr/template.md`. Номер — следующий после максимального.
2. Проверь, не противоречит ли решение существующим ADR. Если заменяет — у нового «Заменяет ADR-NNNN», у старого статус «Заменён ADR-MMMM» (текст старого не переписывай).
3. Заполни шаблон:
   - **Контекст** — конкретная проблема и ограничения (диплом, сроки, стек).
   - **Варианты** — минимум два реальных, с плюсами и минусами. Это пойдёт в текст диплома — без соломенных чучел.
   - **Решение** и **Последствия** — включая, какие файлы `docs/` и код нужно изменить.
4. Статус: «Предложено», если решение ещё не одобрено пользователем; «Принято» — только после явного согласия.
5. Добавь строку в таблицу `docs/adr/README.md`.
6. Если решение меняет требования, модель данных или API — обнови соответствующие файлы `docs/` в том же изменении.
7. Покажи пользователю ADR кратко (решение + главный компромисс) и спроси подтверждение, если статус «Предложено».
