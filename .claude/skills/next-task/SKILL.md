# Выполнить задачу из ROADMAP

Аргумент: `$ARGUMENTS` (ID задачи; если пусто — первая задача со статусом `todo`, у которой все зависимости `done`).

## Текущее состояние

!`git status --short`
!`git branch --show-current`

## Шаги

1. **Найди задачу** в `docs/tasks/ROADMAP.md`: строка в таблице и раздел с критериями. Проверь, что зависимости `done`. Если нет — сообщи и остановись.
2. **Прочитай контекст:** документы и ADR, указанные в «Ссылки», и только их. Посмотри существующий код, который задача затрагивает.
3. **Проверь пробелы.** Если для выполнения нужно решение, которого нет в `docs/` (новая сущность, новая зависимость, отступление от документа), — остановись и задай вопрос или предложи ADR через `/new-adr`. Не придумывай молча.
4. **План.** Выведи: список файлов (создать/изменить), порядок, какие тесты напишешь, как проверишь каждый критерий. Дождись подтверждения пользователя, если задача меняет схему БД, платежи или CatchValidator; иначе продолжай.
5. **Ветка:** `git switch -c t-xx-short-name` от актуальной `main`. Статус задачи в таблице → `doing`.
6. **Реализация** малыми шагами: тест → код → `pnpm typecheck` и тесты затронутого пакета. Коммиты Conventional Commits на английском.
7. **Проверка** перед завершением:
   - `pnpm lint && pnpm typecheck && pnpm test`
   - `pnpm --filter api test:e2e`, если менялся API
   - каждый критерий задачи отмечен `[x]` с доказательством (тест, команда, скриншот)
8. **Документация:**
   - схема/API/правила изменились → обнови соответствующий `docs/0x-*.md`
   - статус задачи → `done`
   - запись в `docs/thesis-log.md` через `/thesis-log`
9. **Ревью:** запусти `/pre-pr`, исправь найденное.
10. **Итог пользователю:** что сделано, что проверено, что осталось/отложено, предложение следующей задачи. PR не создавай и не пушь без явной просьбы.
