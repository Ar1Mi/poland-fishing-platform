# 06. Frontend и PWA

Одно SPA для всех ролей. Офлайн нужен только рыбаку (запись улова, показ QR).

## Claim (T-11)

- `/org`, `/org/:orgId/*`, `/admin/*` обёрнуты в `RequireAuth`: гость уходит на `/login` и после входа возвращается (`state.from`). Дальше доступ решает API: страница показывает его отказ (`ORG_SCOPE_VIOLATION`, `ORG_NOT_ACTIVE`, `FORBIDDEN`) переведённым и не рисует форм — второй копии правил доступа на клиенте нет.
- В шапке авторизованного — иконки «Moje organizacje» (`/org`) и, для суперадмина (`/me.isSuperAdmin`), «Administracja» (`/admin/claims`); на 375 px помещаются вместе с языком и выходом.
- Карточка `UNCLAIMED`-водоёма показывает админу `ACTIVE`-организации ссылку на заявку с `?waterId=` (по одной на организацию, если их несколько). Форма заявки ищет по названию только `UNCLAIMED`-водоёмы; размер и заявленный тип файла проверяет до отправки только ради быстрого ответа — решает API по содержимому.
- Документ заявки скачивается через API-клиент (нужен access-токен): ответ в `Blob`, сохранение через временную ссылку `download`, вставленную в документ (Safari и старый Firefox игнорируют клик по ссылке вне него); object URL освобождается через минуту.
- «Zatwierdź» требует подтверждения: одобрение безвозвратно отклоняет остальные заявки на водоём. После 409 (решил кто-то другой) карточка остаётся с причиной и кнопкой «Odśwież listę» вместо кнопок решения. Успешное решение обновляет очередь и кэш водоёмов (статус на карте и карточке).


## Типы разрешений (T-12)

- `/org/:orgId/permit-types`: список типов организации (цена, срок, льгота, «в продаже» / «продажа приостановлена», водоёмы) и форма создания или правки на месте элемента. Цена вводится в злотых (`25`, `25,50`, `1 250,00`) и переводится в гроши `parsePriceGrosze` из `shared` без float; при правке цена подставляется в формате языка (`formatPriceInput`). Водоёмы — чекбоксы по `GET /orgs/:orgId/waters` с «Zaznacz wszystkie»; единственный водоём организации выбран сразу. Без подключённых водоёмов вместо формы — ссылка на заявку.
- У проданного типа (`inUse`) форма показывает срок, льготу и водоёмы только для чтения с объяснением и отправляет лишь `{ name, priceGrosze }`; кнопки «Usuń» нет — только «Wstrzymaj sprzedaż». Удаление — со вторым подтверждением.
- Карточка подключённого водоёма активной организации показывает типы из `GET /permit-types?waterId=`: название, срок и льгота, цена (Plex Mono). При приостановленной продаже запрос не делается. Кнопка покупки — T-13.

## Покупка (T-13)

- У каждого типа на карточке водоёма — кнопка «Kup» (48 px) со ссылкой `/buy/:permitTypeId?waterId=`. Страница покупки (`RequireAuth`) берёт тип из предложения этого водоёма (`GET /permit-types?waterId=`): отдельного публичного `GET /permit-types/:id` нет, а водоём нужен и для заголовка. Типа в предложении нет (снят с продажи, ссылка без водоёма) → «nie jest już sprzedawany» и ссылка назад.
- Дата — нативное `input type="date"` с `min`/`max`; окно проверяет `permitStartFormSchema(today)` из `shared` (сегодня по Варшаве фиксируется при открытии страницы). Под полем — «Ważne od … do … włącznie» по `permitValidTo`; у льготного типа — условие возраста из `DISCOUNT_AGE`. Отказ API (`DISCOUNT_NOT_ELIGIBLE`, `PERMIT_TYPE_INACTIVE` …) — переведённый `ApiErrorAlert`.
- После `POST /permits` — полная загрузка `paymentUrl` (`shared/lib/redirect.ts`, в тестах подменяется): страница оплаты принадлежит провайдеру.
- `/payment/fake/:sessionId` (без входа, как у P24): сумма и название из адреса — только для показа; «Zapłać» / «Odrzuć» вызывают `POST /payments/fake/:sessionId/complete` и возвращают на `returnUrl` только внутри приложения (`safeReturnPath`).
- `/payment/return?permitId=` (`RequireAuth`) спрашивает `GET /me/permits/:id` каждые 2 с, пока разрешение `PENDING_PAYMENT` и с начала опроса прошло меньше 60 с (`refetchInterval` TanStack Query). Итог: оплачено (`PermitTicket` с QR, организация, тип, цена, ссылка на `/me/permits/:id`), отменено, или «ещё не подтверждено» с кнопкой «Sprawdź ponownie», которая начинает новый круг опроса.
- `WaterCard` в списке каталога показывает «od …» у подключённых водоёмов: один запрос `GET /permit-types/lowest-prices` по id подключённых водоёмов из показанных (до `LIST_LIMIT`), прежние цены остаются на экране, пока карта двигается.
## Мои разрешения (T-15)

- `/me/permits` (`RequireAuth`, иконка «Moje zezwolenia» в шапке): «Aktualne» (`ACTIVE`, `SCHEDULED`, `PENDING_PAYMENT`) и «Archiwalne» (остальные); карточка — тип, организация, номер, срок, статус, ссылка на разрешение.
- `/me/permits/:id`: `PermitTicket` (тёмная шапка с типом и статусом, QR `qrcode.react` — SVG, уровень коррекции M, номер текстом, срок), детали и «Pobierz PDF» (blob с токеном доступа, `shared/lib/save-file.ts`). QR и PDF — только если API дал `qrToken`.
- QR кодирует `new URL('/verify/' + qrToken, location.origin)` (`features/permits/lib/verify-url.ts`): сайт отдаётся с `WEB_URL`, поэтому адрес совпадает с адресом в PDF.
- «Pokaż kod na pełnym ekranie» — слой поверх всего (`role="dialog"`, `aria-modal`): QR по меньшей стороне экрана, номер Plex Mono, подсказка про яркость; фокус на «Zamknij»; остальная страница получает `inert` (нет фокуса по Tab, скрыта от скринридера), прокрутка `body` заблокирована; Escape закрывает и возвращает фокус.
- В шапке на ширине < 640 px иконка панели суперадмина скрыта: четыре иконки 44 px и переключатель языка не помещаются в 375 px. Панель — экран для десктопа.

## Реестр уловов (T-18)

- `/catch/new` (`RequireAuth`) — один экран формы и экран вердикта (NFR-06). Водоём — из водоёмов `ACTIVE`-разрешений (`waters` в `/me/permits`); если водоём покрывают два разрешения, в списке есть оба с названием типа. Вид — по алфавиту языка интерфейса (API отдаёт порядок сортировки БД). «Zabrana / Wypuszczona» — `SegmentedToggle` (`aria-pressed`) без значения по умолчанию: выбор обязателен. Длина — целые см, вес — кг с запятой или точкой (`1,25`, `parseWeightKg` в `shared` переводит в граммы без float), время — `datetime-local` по варшавскому времени (`fromWarsawDateTimeLocal`), по умолчанию «сейчас». Проверка формы — `catchFormSchema` из `shared`. «Dodaj moją lokalizację» — `navigator.geolocation` по кнопке, координаты округляются до 5 знаков (~1 м); без поддержки кнопки нет.
- Последние водоём и вид подставляются (`localStorage`, `lowisko.catch.last` — только id, не чувствительно). `clientId` — один на экран (`newClientId`: `crypto.randomUUID`, а без защищённого контекста — `getRandomValues`, иначе страница падала бы при проверке с телефона по `http://192.168…`). Если ответа нет (сеть, 5xx), улов мог сохраниться: поля замораживаются, остаётся «Wyślij ponownie» — тот же улов с тем же id, иначе сохранённый вердикт не совпал бы с экраном. Ответ 4xx ничего не сохранил — форма остаётся открытой для правки. Если разрешения перезагрузились и выбранного места больше нет, форма берёт первое.
- Отправка — `POST /catches/sync` с одним уловом. Вердикт сервера показывается сразу; фокус переходит на заголовок вердикта. Срок правки отклонённого называется, только если окно ещё открыто (улов с ошибкой в дате сохраняется уже за окном). Причины отказа — `RuleAlert`: перевод кода с `details` (длина, период, лимит, вес) и мелкой строкой `BR-xx · CODE`. Проверка `validateCatch` до отправки — в T-21 вместе с офлайн-данными.
- `/me/catches` — сезон (варшавский год, `?season=`, последние 5 лет) по дням, новые сверху; `CatchRow`: вид, «Zabrana / Wypuszczona» и время, справа длина и вес (Plex Mono), водоём, статус, причины отказа. Пока открыто окно BR-07 (`editableUntil`, точное время на экране) — «Popraw» (та же форма на месте карточки; водоёмы — только своего разрешения; неизменённое время не отправляется, чтобы не потерять секунды) и «Usuń» со вторым подтверждением. Фокус не теряется: в форму правки (заголовок), на «Anuluj» подтверждения, обратно на открывшую кнопку; после удаления — на сообщение об удалении. Ошибка удаления (например, окно закрылось) остаётся видна и после того, как строка стала закрытой.
- Ссылки «Dodaj połów» (accent, при `ACTIVE`-разрешении) и «Rejestr połowów» — на `/me/permits`; «Dodaj połów» — и на странице активного разрешения. В шапку не добавлены: на 375 px четвёртая иконка не помещается (нижняя навигация рыбака — `BottomNav` из дизайн-системы, вместе с PWA).

## Каталог (T-09)

- `/` — карта и список под ней (`features/catalog`). Фильтры `region`, `type`, `status`, `q` хранятся в URL (ссылкой можно поделиться, работает «назад»); неизвестное значение в URL игнорируется.
- Без поиска карта запрашивает только свою видимую область (`bbox`, округление до 5 знаков); первый запрос уходит, когда карта сообщила реальные границы. Поиск по названию идёт по всему каталогу и приближает карту к результатам (после их прихода, не к прежним данным). «Wróć do mapy» возвращает по истории — с прежними фильтрами.
- Список под картой — доступная альтернатива маркерам, рисует не больше 100 записей; при `truncated` — подсказка «приблизьте карту» (в режиме поиска — «уточните название»).
- Маркер подключённого водоёма — заливка, «только реестр» — кольцо (не только цвет); статус текстом — в попапе и списке. Селекты фильтров на телефоне свёрнуты в «Filtry», чтобы карта была на первом экране.
- Страница отправляет `no-referrer` (`index.html`), а политика тайлов OSM требует Referer: у `TileLayer` `referrerPolicy="origin"` — только origin.
- Ссылка `externalInfoUrl` из импортированных данных показывается, только если это http(s).

## Офлайн

Таблицы Dexie:

| Таблица | Содержимое |
| --- | --- |
| `permits` | Активные и будущие разрешения (платформенные и внешние) + `qrToken` |
| `rules` | Эффективные правила по `permitId` (из `/offline-bundle`) |
| `species`, `waters` | Справочники для формы улова (водоёмы — только из разрешений) |
| `catchQueue` | Уловы: `clientId`, данные, `status: PENDING_SYNC / ACCEPTED / REJECTED`, `violations` |

Поток:

1. После оплаты и при каждом открытии онлайн — обновить `permits`/`rules` из `/offline-bundle`.
2. Форма улова вызывает `validateCatch` из `packages/shared` и сразу показывает нарушения.
3. Запись → `catchQueue` со статусом `PENDING_SYNC`.
4. Синхронизация: при событии `online`, при открытии приложения и по кнопке «Синхронизировать» — пакетами по 50 на `/catches/sync`.
5. Ответ обновляет статусы; `REJECTED` показываются с переведённой причиной.

Background Sync API не используется: его нет в Safari/iOS.

Workbox: app shell и статика — precache; `/api/v1/waters`, `/species` — StaleWhileRevalidate; остальное API — NetworkOnly (данные кэшируются в Dexie, а не в Service Worker). Тайлы карты — CacheFirst с лимитом 500 записей.

## API-клиент

- `pnpm gen:api`: API собирается и без БД и `.env` выгружает OpenAPI-документ (`apps/api/dist-openapi/openapi.json`, отдельно от `dist`, чтобы не мешать `nest start --watch`), `openapi-typescript` делает из него `src/shared/api/schema.d.ts`. Файл не коммитится; корневые `pnpm lint` и `pnpm typecheck` генерируют его сами.
- Клиент — `openapi-fetch`, пути с префиксом `/api/v1`, тот же origin: в dev Vite проксирует `/api` на `localhost:3000`, в prod — Caddy.
- Запросы идут только через `request()` внутри TanStack Query: он возвращает `data` или бросает `ApiError` с `code`. Компонент показывает `t(errorMessageKey(error))` (`ApiErrorAlert`).
- Кроме кодов API (`ErrorCode`) у клиента два своих: `NETWORK_ERROR` — ответа нет или прокси вернул 502/503/504 без тела API; `UNKNOWN_ERROR` — ответ не в формате `{ code }` или код неизвестен клиенту.
- Повторы: ответы 4xx не повторяются, сеть и 5xx — до двух раз.

## i18n

- Языки `pl` (по умолчанию), `en`, `ru`; файлы `src/shared/i18n/locales/{lng}/{ns}.json`. `ns` — фича; при загрузке файлы сливаются в одно пространство i18next под именем фичи, поэтому ключ — `home.page.title`, а не `home:page.title`. Ключи проверяет компилятор по ресурсам `pl`.
- Язык выбирается переключателем в шапке и запоминается в `localStorage` (`lowisko.locale`); определения по языку браузера нет. После входа (T-07) язык будет браться из профиля.
- Никаких строк в JSX — только `t('catch.form.length')`. Ключи — `feature.component.element`.
- Ошибки API переводятся по `code`: `t('errors.' + code)`.
- До этапа локализации допустимо заполнять только `pl`; пропущенные ключи в `en`/`ru` подхватывает fallback на `pl`.
- Даты и числа — `Intl` с локалью пользователя, часовой пояс `Europe/Warsaw`.

## UI-принципы

Цвета, типографика, отступы и компоненты — в `10-design-system.md`.

- Mobile-first: основной сценарий — телефон на берегу, одной рукой, на солнце. Крупные цели нажатия (≥ 44 px), высокий контраст.
- Форма улова ≤ 3 шагов (NFR-06): последние вид и водоём подставляются по умолчанию.
- QR — на весь экран, с подсказкой увеличить яркость и номером разрешения текстом.

## Проверка QR и протоколы (T-19)

- `/verify/:token` открыт всем (без `RequireAuth`): камера телефона открывает его из QR. Запрос ждёт восстановления сессии (`status !== 'restoring'`), ключ запроса включает статус сессии — после входа или выхода на странице ответ запрашивается снова. Расширенную часть решает API; на клиенте нет копии правил доступа.
- Вердикт — `VerdictBanner` (заливка Success/Danger на всю ширину на телефоне, иконка 56 px, H1 «Zezwolenie ważne / nieważne»); у недействительного — причина по статусу (`SCHEDULED` — с какой даты, `EXPIRED`, `REVOKED` …) или «код неверный, подделан или истёк». Под ним — карточка: тип и статус, организация, срок, инициалы, водоёмы.
- Гость видит «Zaloguj się jako strażnik» (`/login` с `state.from`, после входа — обратно на проверку); вошедший без права — пояснение, что больше видят только инспекторы и админы организации-владельца.
- Инспектор и админ организации: «Dane do kontroli» (имя, фамилия, год рождения — сверить с документом, номер разрешения Plex Mono), «Połowy dzisiaj» — `CatchSummary` (вид, «Zabrana / Wypuszczona» и время, длина и вес, водоём, статус, причины отказа; общий с `CatchRow` реестра) и пометка, что видны только уже отправленные уловы. Форма протокола: результат — `SegmentedToggle` «Bez zastrzeżeń / Naruszenie» без значения по умолчанию, «Uwagi» до 2000 знаков, «Dodaj moją lokalizację» (`LocationField` из `shared/ui`, общий с формой улова), проверка — `inspectionFormSchema` из `shared`. После сохранения форма заменяется подтверждением «Protokół zapisany o …», фокус — на нём.
- `/org/:orgId/inspections` (`RequireAuth`, ссылка «Protokoły kontroli» у админа в `/org`): сезон (`?season=`, последние 5 лет), карточки — время, результат (иконка + текст), номер и тип разрешения, владелец, инспектор, заметки. Отказ API (`FORBIDDEN` у инспектора) — переведённый `ApiErrorAlert`. Инспектору в `/org` — подсказка, что проверка начинается со сканирования QR.
