# 06. Frontend и PWA

Одно SPA для всех ролей. Офлайн нужен только рыбаку (запись улова, показ QR).

## Claim (T-11)

- `/org`, `/org/:orgId/*`, `/admin/*` обёрнуты в `RequireAuth`: гость уходит на `/login` и после входа возвращается (`state.from`). Дальше доступ решает API: страница показывает его отказ (`ORG_SCOPE_VIOLATION`, `ORG_NOT_ACTIVE`, `FORBIDDEN`) переведённым и не рисует форм — второй копии правил доступа на клиенте нет.
- В шапке авторизованного — иконки «Moje organizacje» (`/org`) и, для суперадмина (`/me.isSuperAdmin`), «Administracja» (`/admin/claims`); на 375 px помещаются вместе с языком и выходом.
- Карточка `UNCLAIMED`-водоёма показывает админу `ACTIVE`-организации ссылку на заявку с `?waterId=` (по одной на организацию, если их несколько). Форма заявки ищет по названию только `UNCLAIMED`-водоёмы; размер и заявленный тип файла проверяет до отправки только ради быстрого ответа — решает API по содержимому.
- Документ заявки скачивается через API-клиент (нужен access-токен): ответ в `Blob`, сохранение через временную ссылку `download`, вставленную в документ (Safari и старый Firefox игнорируют клик по ссылке вне него); object URL освобождается через минуту.
- «Zatwierdź» требует подтверждения: одобрение безвозвратно отклоняет остальные заявки на водоём. После 409 (решил кто-то другой) карточка остаётся с причиной и кнопкой «Odśwież listę» вместо кнопок решения. Успешное решение обновляет очередь и кэш водоёмов (статус на карте и карточке).


## Типы разрешений (T-12)

- `/org/:orgId/permit-types`: список типов организации (цена, срок, льгота, «в продаже» / «продажа приостановлена», водоёмы) и форма создания или правки на месте элемента. Цена вводится в злотых (`25`, `25,50`, `1 250,00`) и переводится в гроши `parsePriceGrosze` из `shared` без float; при правке цена подставляется в формате языка (`formatPriceInput`). Водоёмы — чекбоксы по `GET /orgs/:orgId/waters` с «Zaznacz wszystkie»; единственный водоём организации выбран сразу. Без подключённых водоёмов вместо формы — ссылка на заявку.
- У проданного типа (`inUse`) форма показывает срок, льготу и водоёмы только для чтения с объяснением и отправляет лишь `{ name, priceGrosze }`; кнопки «Usuń» нет — только «Wstrzymaj sprzedaż». Удаление — со вторым подтверждением.
- Карточка подключённого водоёма активной организации показывает типы из `GET /permit-types?waterId=`: название, срок и льгота, цена (Plex Mono). При приостановленной продаже запрос не делается. Кнопка покупки — T-13.

## Покупка (T-13)

- У каждого типа на карточке водоёма — кнопка «Kup» (48 px) со ссылкой `/buy/:permitTypeId?waterId=`. Страница покупки (`RequireAuth`) берёт тип из предложения этого водоёма (`GET /permit-types?waterId=`): отдельного публичного `GET /permit-types/:id` нет, а водоём нужен и для заголовка. Типа в предложении нет (снят с продажи, ссылка без водоёма) → «nie jest już sprzedawany» и ссылка назад.
- Дата — нативное `input type="date"` с `min`/`max`; окно проверяет `permitStartFormSchema(today)` из `shared` (сегодня по Варшаве фиксируется при открытии страницы). Под полем — «Ważne od … do … włącznie» по `permitValidTo`; у льготного типа — условие возраста из `DISCOUNT_AGE`. Отказ API (`DISCOUNT_NOT_ELIGIBLE`, `PERMIT_TYPE_INACTIVE` …) — переведённый `ApiErrorAlert`.
- После `POST /permits` — полная загрузка `paymentUrl` (`shared/lib/redirect.ts`, в тестах подменяется): страница оплаты принадлежит провайдеру.
- `/payment/fake/:sessionId` (без входа, как у P24): сумма и название из адреса — только для показа; «Zapłać» / «Odrzuć» вызывают `POST /payments/fake/:sessionId/complete` и возвращают на `returnUrl` только внутри приложения (`safeReturnPath`).
- `/payment/return?permitId=` (`RequireAuth`) спрашивает `GET /me/permits/:id` каждые 2 с, пока разрешение `PENDING_PAYMENT` и с начала опроса прошло меньше 60 с (`refetchInterval` TanStack Query). Итог: оплачено (`PermitTicket` с QR, организация, тип, цена, ссылка на `/me/permits/:id`), отменено, или «ещё не подтверждено» с кнопкой «Sprawdź ponownie», которая начинает новый круг опроса.
- `WaterCard` в списке каталога показывает «od …» у подключённых водоёмов: один запрос `GET /permit-types/lowest-prices` по id подключённых водоёмов из показанных (до `LIST_LIMIT`), прежние цены остаются на экране, пока карта двигается.
## Мои разрешения (T-15)

- `/me/permits` (`RequireAuth`, иконка «Moje zezwolenia» в шапке): «Aktualne» (`ACTIVE`, `SCHEDULED`, `PENDING_PAYMENT`) и «Archiwalne» (остальные); карточка — тип, организация, номер, срок, статус, ссылка на разрешение.
- `/me/permits/:id`: `PermitTicket` (тёмная шапка с типом и статусом, QR `qrcode.react` — SVG, уровень коррекции M, номер текстом, срок), детали и «Pobierz PDF» (blob с токеном доступа, `shared/lib/save-file.ts`). QR и PDF — только если API дал `qrToken`.
- QR кодирует `new URL('/verify/' + qrToken, location.origin)` (`features/permits/lib/verify-url.ts`): сайт отдаётся с `WEB_URL`, поэтому адрес совпадает с адресом в PDF.
- «Pokaż kod na pełnym ekranie» — слой поверх всего (`role="dialog"`, `aria-modal`): QR по меньшей стороне экрана, номер Plex Mono, подсказка про яркость; фокус на «Zamknij»; остальная страница получает `inert` (нет фокуса по Tab, скрыта от скринридера), прокрутка `body` заблокирована; Escape закрывает и возвращает фокус.
- В шапке на ширине < 640 px иконка панели суперадмина скрыта: четыре иконки 44 px и переключатель языка не помещаются в 375 px. Панель — экран для десктопа.

## Реестр уловов (T-18)

- `/catch/new` (`RequireAuth`) — один экран формы и экран вердикта (NFR-06). Водоём — из водоёмов `ACTIVE`-разрешений (`waters` в `/me/permits`); если водоём покрывают два разрешения, в списке есть оба с названием типа. Вид — по алфавиту языка интерфейса (API отдаёт порядок сортировки БД). «Zabrana / Wypuszczona» — `SegmentedToggle` (`aria-pressed`) без значения по умолчанию: выбор обязателен. Длина — целые см, вес — кг с запятой или точкой (`1,25`, `parseWeightKg` в `shared` переводит в граммы без float), время — `datetime-local` по варшавскому времени (`fromWarsawDateTimeLocal`), по умолчанию «сейчас». Проверка формы — `catchFormSchema` из `shared`. «Dodaj moją lokalizację» — `navigator.geolocation` по кнопке, координаты округляются до 5 знаков (~1 м); без поддержки кнопки нет.
- Последние водоём и вид подставляются (`localStorage`, `lowisko.catch.last` — только id, не чувствительно). `clientId` — один на экран (`newClientId`: `crypto.randomUUID`, а без защищённого контекста — `getRandomValues`, иначе страница падала бы при проверке с телефона по `http://192.168…`). Если разрешения перезагрузились и выбранного места больше нет, форма берёт первое. (До T-21 улов без ответа замораживал форму с «Wyślij ponownie»; с T-21 любой улов сначала ложится в очередь на устройстве — см. «Офлайн (T-21)».)
- Отправка — `POST /catches/sync` (с T-21 — из очереди на устройстве). Вердикт сервера показывается сразу; фокус переходит на заголовок вердикта. Срок правки отклонённого называется, только если окно ещё открыто (улов с ошибкой в дате сохраняется уже за окном). Причины отказа — `RuleAlert`: перевод кода с `details` (длина, период, лимит, вес) и мелкой строкой `BR-xx · CODE`. Проверка `validateCatch` до отправки — с T-21.
- `/me/catches` — сезон (варшавский год, `?season=`, последние 5 лет) по дням, новые сверху; `CatchRow`: вид, «Zabrana / Wypuszczona» и время, справа длина и вес (Plex Mono), водоём, статус, причины отказа. Пока открыто окно BR-07 (`editableUntil`, точное время на экране) — «Popraw» (та же форма на месте карточки; водоёмы — только своего разрешения; неизменённое время не отправляется, чтобы не потерять секунды) и «Usuń» со вторым подтверждением. Фокус не теряется: в форму правки (заголовок), на «Anuluj» подтверждения, обратно на открывшую кнопку; после удаления — на сообщение об удалении. Ошибка удаления (например, окно закрылось) остаётся видна и после того, как строка стала закрытой.
- Ссылки «Dodaj połów» (accent, при `ACTIVE`-разрешении) и «Rejestr połowów» — на `/me/permits`; «Dodaj połów» — и на странице активного разрешения. В шапку не добавлены: на 375 px четвёртая иконка не помещается; с T-21 реестр открывается из нижней навигации.

## Каталог (T-09)

- `/` — карта и список под ней (`features/catalog`). Фильтры `region`, `type`, `status`, `q` хранятся в URL (ссылкой можно поделиться, работает «назад»); неизвестное значение в URL игнорируется.
- Без поиска карта запрашивает только свою видимую область (`bbox`, округление до 5 знаков); первый запрос уходит, когда карта сообщила реальные границы. Поиск по названию идёт по всему каталогу и приближает карту к результатам (после их прихода, не к прежним данным). «Wróć do mapy» возвращает по истории — с прежними фильтрами.
- Список под картой — доступная альтернатива маркерам, рисует не больше 100 записей; при `truncated` — подсказка «приблизьте карту» (в режиме поиска — «уточните название»).
- Маркер подключённого водоёма — заливка, «только реестр» — кольцо (не только цвет); статус текстом — в попапе и списке. Селекты фильтров на телефоне свёрнуты в «Filtry», чтобы карта была на первом экране.
- Страница отправляет `no-referrer` (`index.html`), а политика тайлов OSM требует Referer: у `TileLayer` `referrerPolicy="origin"` — только origin.
- Ссылка `externalInfoUrl` из импортированных данных показывается, только если это http(s).

## Офлайн

Таблицы Dexie (база `lowisko`, `shared/offline/db.ts`):

| Таблица | Содержимое |
| --- | --- |
| `meta` | `owner`: чьи данные на устройстве (`userId`) и когда они обновлены онлайн (`refreshedAt`) |
| `permits` | Разрешения из `/offline-bundle` с `qrToken`: `ACTIVE`, `SCHEDULED` и закончившееся вчера |
| `externalPermits` | Внешние разрешения (T-22, версия базы 2) из `/me/external-permits/:id/offline-bundle` — по тому же правилу `keptOnDevice`; без фото |
| `rules` | Эффективные правила водоёмов разрешения по `permitId` (из `/offline-bundle`); у внешнего — общие правила на каждом его водоёме |
| `species` | Справочник видов с `isProtected` (`GET /species`). Отдельной таблицы водоёмов нет: названия приходят в `permits[].waters` |
| `catchQueue` | Уловы устройства: `clientId`, `userId`, данные (тело `SyncCatchItemDto`), `status: PENDING_SYNC / ACCEPTED / REJECTED / FAILED`, `violations`, `errorCode` |

Поток:

1. После оплаты и при каждом открытии онлайн — обновить `permits`/`rules`/`species` из `/offline-bundle`.
2. Форма улова вызывает `validateCatch` из `packages/shared` и сразу показывает нарушения.
3. Запись → `catchQueue` со статусом `PENDING_SYNC`.
4. Синхронизация: при событии `online`, при открытии приложения и по кнопке «Синхронизировать» — пакетами по 50 на `/catches/sync`.
5. Ответ обновляет статусы; `REJECTED` показываются с переведённой причиной.

Background Sync API не используется: его нет в Safari/iOS.

Workbox: app shell и статика — precache; `/api/v1/waters` — StaleWhileRevalidate, `/species` — NetworkFirst (T-21: копия справочника на устройстве, с `isProtected`, должна быть текущей); остальное API — NetworkOnly (данные кэшируются в Dexie, а не в Service Worker). Тайлы карты — CacheFirst с лимитом 500 записей.

### Офлайн (T-21)

- **PWA:** `vite-plugin-pwa` (`generateSW`): манифест (`pl`, `standalone`, `theme_color` Toń 900, фон экрана), иконки 192/512, maskable 512 и apple-touch 180 — поплавок на Toń 900, исходник `public/favicon.svg`; PNG отрендерены из SVG один раз Chromium из Playwright и лежат в `public/`. `registerType: 'autoUpdate'`: новая версия сразу берёт управление и перезагружает страницу (очередь в IndexedDB не теряется). Навигация без сети отдаёт `index.html` из precache, `/api/*` в него не попадает. Водоёмы (`/api/v1/waters…`) — StaleWhileRevalidate до 200 ответов, виды (`/species`) — NetworkFirst с тайм-аутом 5 с; тайлы OSM — CacheFirst, 500 записей (ответы без CORS, «непрозрачные»). Регистрация — `registerSW({ immediate: true })` в `main.tsx`; в `pnpm dev` service worker не работает.
- **Обновление данных устройства** (`refreshAndSync`, `shared/offline/device-data.ts`): `/me`, `/me/permits`, `/species` и `/offline-bundle` каждого сохраняемого разрешения, затем запись одной транзакцией, которая заменяет всё. Данные другого пользователя не остаются рядом, его неотправленные уловы — остаются (привязаны к `userId`). Запускается `DeviceSync` (в `App`, вне маршрутов) при входе и открытии, при событии `online` и страницей возврата после оплаты. Цикл: `/me`, затем обновление разрешений и, даже если оно не удалось, отправка очереди этого пользователя. Циклы идут друг за другом: вызов во время цикла получает следующий (разрешение, оплаченное во время цикла, тоже попадёт на устройство). Данные, полученные для сессии, которая за это время закончилась (выход, другой вход), не записываются — счётчик поколения сессии в `session.ts`. Это не данные экрана, поэтому слой обращается к типизированному клиенту без TanStack Query.
- **Офлайн-сессия** (ADR-0013): при старте без сети (refresh не прошёл не по 401) устройство действует за владельца данных, если они обновлены не дольше 7 дней назад: статус `offline`, без токена. Работают `/catch/new`, `/me/permits`, `/me/permits/:id`, `/me/catches` (`RequireAuth offline`); другие закрытые страницы — «Brak połączenia z siecią» и ссылки на них. В шапке — бейдж «Offline» вместо меню. Выхода без сети нет. Refresh при старте ждёт не дольше 8 с: у водоёма сеть часто только кажется рабочей, а пустой экран вместо формы хуже офлайн-режима. При `online` и при возвращении на вкладку — тихий refresh; пока профиль заново грузится, сессия помнит того же пользователя (`getCarriedUserId`) — для показа, но не для отправки: уловы уходят только от пользователя токена (`useVerifiedUserId`, `/me`). Отказ refresh (401) стирает с устройства владельца и его разрешения: офлайн работает только тот, кто мог бы войти онлайн; неотправленные уловы ждут его входа. Выход стирает данные пользователя с устройства, при неотправленных уловах — после `confirm`; без сети кнопки выхода нет (бейдж «Offline»).
- **Форма улова** работает только из IndexedDB, онлайн и офлайн одинаково. Места — разрешения, `ACTIVE` сейчас (статус пересчитывается на устройстве: `SCHEDULED` становится `ACTIVE` в полночь и без сети) или закончившиеся вчера: вчерашний улов в последний день разрешения записывается (BR-01 — на `caughtAt`), у такого места подпись «(ważne do …)». Пока вводятся данные, `validateCatch` проверяет улов. Нарушения — `RuleAlert` в `aria-live="polite"`, «Zapisz połów» недоступна (решение пользователя: обычно рыбу нужно отпустить). Без нарушений — «Zgodne z zasadami łowiska». `sameDayKept` — принятые оставленные уловы суток со всех водоёмов: если реестр сервера загружен, он решает за все свои уловы, а устройство добавляет только ещё не отправленные (`PENDING_SYNC`); без него — уловы устройства `PENDING_SYNC` и `ACCEPTED`. Правка и удаление в реестре обновляют очередь (`reflectStored`, `forgetQueued`), чтобы удалённый улов не занимал лимит и без сети. Правило вида на водоёме — из `rules` разрешения, без правила — «без ограничений». Окончательное решение — за сервером: другой телефон, изменённые правила.
- **Запись и вердикт:** улов ложится в очередь, экран вердикта читает его строку из IndexedDB и меняется по мере ответа: «Zapisano na urządzeniu» → «Połów zapisany w rejestrze» / «Połów odrzucony» с причинами / «Nie udało się wysłać połowu» (`FAILED`). С сетью экран сразу отправляет очередь. Без ответа (сеть, 5xx) улов ждёт на устройстве с тем же `clientId`, есть «Wyślij teraz». Фокус — на одном заголовке, который меняет текст.
- **Очередь** (`syncCatchQueue`): уловы пользователя `PENDING_SYNC` в порядке `caughtAt`, затем `clientId` (как проверяет сервер), пакетами по 50; одновременные вызовы делят один прогон. Вызов во время прогона получает следующий прогон, который прочитает очередь заново: улов, сохранённый на медленной сети, уходит этим же вызовом. Пакет ждёт ответа не дольше 20 с. Отказ пакета — только 400 `VALIDATION_FAILED` API (`05-api.md`): такой пакет отправляется по одному улову, и улов, который и один получает отказ, становится `FAILED` с кодом и больше не отправляется (его можно только удалить). Всё прочее — сеть, тайм-аут, 5xx, 401, 429, 4xx прокси, до которого API не дошло, — останавливает прогон, уловы ждут. Перед отправкой у строк ставится `sentAt`: отправленный без ответа улов мог сохраниться, поэтому на устройстве его не удалить — только в реестре после синхронизации. Уловы с вердиктом остаются на устройстве, пока открыто их окно BR-07 (они нужны лимитам суток), и удаляются в начале следующей синхронизации.
- **Реестр** `/me/catches`: над сезоном — «Na tym urządzeniu», уловы `PENDING_SYNC` (`StatusBadge pendingSync` «Do synchronizacji», пунктир) и `FAILED` («Nie wysłano» и причина), «Synchronizuj» (только с сетью и при ждущих), «Usuń» со вторым подтверждением (кроме отправленных без ответа — для них подсказка). Без сети реестр сервера не запрашивается — вместо него предупреждение.
- **Разрешения** `/me/permits`, `/me/permits/:id`: без сети или в офлайн-сессии — из IndexedDB, с предупреждением «stan z ostatniego połączenia», QR из сохранённого `qrToken` — только пока пересчитанный на устройстве статус `SCHEDULED` или `ACTIVE`, как отдаёт сервер; без PDF.
- **`BottomNav`** (телефон, < 768 px, для вошедшего и офлайн): «Łowiska», «Zezwolenia», «Połowy» (активен и на `/catch/new`, `aria-current="page"`). Четвёртый раздел «Profil» появится вместе с `/me/profile`. Иконка разрешений в шапке на телефоне скрыта.
- **Ограничение:** без IndexedDB (хранилище сайта заблокировано) форма улова не работает: она пишет, что на устройстве нет разрешений, а если запись в очередь не удалась — «Nie udało się zapisać połowu na urządzeniu».

## Внешние разрешения (T-22)

- `/me/external-permits` (`RequireAuth`, только онлайн: разрешение вносится с сервером) — карточки: выдавший, номер, водоёмы, срок, статус, «Ze zdjęciem»; «Dodaj zezwolenie». Ссылка — в разделе «Zezwolenia zewnętrzne» на `/me/permits` (кроме офлайн-сессии) и на карточке неподключённого водоёма: «Dodaj zezwolenie zewnętrzne na to łowisko» ведёт на `/me/external-permits/new?waterId=` — водоём уже выбран.
- **Форма** (`ExternalPermitForm`, схема `externalPermitFormSchema` из `shared`): «Wydał», номер (необязателен), «Ważne od / do» (`type="date"`), водоёмы — поиск по названию по всему каталогу (как в форме claim, но без фильтра статуса; Enter ищет, это не вложенная форма), выбранные — кнопки-«чипы» «Usuń łowisko …» (до 20), фото — `FileField` (тип и 5 МБ проверяются до отправки, окончательно — API по содержимому). Ошибка дат — под «Ważne do» с причиной (`ExternalPermitDatesIssue`) и видна сразу, даже если другие поля ещё неверны. Сохранение — `POST`, затем `PUT …/photo`; отказ фото не отменяет сохранённое разрешение: карточка открывается с предупреждением, фото можно добавить там.
- **Карточка** `/me/external-permits/:id`: H1 — выдавший, статус, номер, срок, водоёмы, пояснение про общие правила; «Dodaj połów» при `ACTIVE`; «Popraw dane» — та же форма на месте (подсказка: сохранённые уловы не перепроверяются). Фото: «Pobierz» (через токен, `saveFile`), «Usuń zdjęcie», замена. «Rejestr połowów dla użytkownika rybackiego» — сезоны, которые покрывает разрешение (выбор, если их два), «Pobierz rejestr <год> (PDF)». «Usuń zezwolenie» со вторым подтверждением (фокус на «Nie usuwaj», после отказа — обратно); `EXTERNAL_PERMIT_IN_USE` — переведённая причина. Пока на этом устройстве ждут отправки (`PENDING_SYNC`) уловы на этом разрешении, кнопки нет — вместо неё пояснение и ссылка на реестр: на сервере уловов ещё нет, удаление прошло бы, а уловы стали бы `FAILED` навсегда. H1 остаётся и в режиме правки; фокус — на заголовок формы и обратно на «Popraw dane», после выбора или удаления водоёма — в поле поиска, после удаления фото — на заголовок карточки фото. Предупреждение о неудавшемся фото берёт из `history.state` ключ перевода (не объект ошибки: structured clone теряет его поля) и пропадает, как только фото есть.
- **После любой правки** (добавление, изменение, фото, удаление) — `refreshAndSync()`: форма улова берёт разрешения только с устройства, новое внешнее разрешение должно туда попасть.
- **Форма улова и реестр:** места — водоёмы разрешений обоих видов (`PlacePermit`: `platformPlacePermit` / `externalPlacePermit`); если водоём покрывают два разрешения, у внешнего в списке — выдавший. Статус внешнего на устройстве — `externalPermitStatus` на «сейчас». `checkOnDevice` находит разрешение по id среди обоих видов: у внешнего BR-01 — только даты и водоёмы, правила — общие из его пакета. Улов уходит с `externalPermitId` (`permitId: null`); в очереди устройства («Na tym urządzeniu») название водоёма ищется среди водоёмов разрешений обоих видов. Правка в реестре (`CatchRow`) предлагает водоёмы разрешения улова любого вида (`/me/permits` и `/me/external-permits`).

## API-клиент

- `pnpm gen:api`: API собирается и без БД и `.env` выгружает OpenAPI-документ (`apps/api/dist-openapi/openapi.json`, отдельно от `dist`, чтобы не мешать `nest start --watch`), `openapi-typescript` делает из него `src/shared/api/schema.d.ts`. Файл не коммитится; корневые `pnpm lint` и `pnpm typecheck` генерируют его сами.
- Клиент — `openapi-fetch`, пути с префиксом `/api/v1`, тот же origin: в dev Vite проксирует `/api` на `localhost:3000`, в prod — Caddy.
- Запросы идут только через `request()` внутри TanStack Query: он возвращает `data` или бросает `ApiError` с `code`. Компонент показывает `t(errorMessageKey(error))` (`ApiErrorAlert`).
- Кроме кодов API (`ErrorCode`) у клиента два своих: `NETWORK_ERROR` — ответа нет или прокси вернул 502/503/504 без тела API; `UNKNOWN_ERROR` — ответ не в формате `{ code }` или код неизвестен клиенту.
- Повторы: ответы 4xx не повторяются, сеть и 5xx — до двух раз.

## i18n

- Языки `pl` (по умолчанию), `en`, `ru`; файлы `src/shared/i18n/locales/{lng}/{ns}.json`. `ns` — фича; при загрузке файлы сливаются в одно пространство i18next под именем фичи, поэтому ключ — `home.page.title`, а не `home:page.title`. Ключи проверяет компилятор по ресурсам `pl`.
- Язык выбирается переключателем в шапке и запоминается в `localStorage` (`lowisko.locale`); определения по языку браузера нет. После входа (T-07) язык будет браться из профиля.
- Никаких строк в JSX — только `t('catch.form.length')`. Ключи — `feature.component.element`.
- Ошибки API переводятся по `code`: `t('errors.' + code)`.
- До этапа локализации допустимо заполнять только `pl`; пропущенные ключи в `en`/`ru` подхватывает fallback на `pl`.
- Даты и числа — `Intl` с локалью пользователя, часовой пояс `Europe/Warsaw`.

## Админка организации (T-23)

- `/org/new` — форма `createOrganizationSchema` из `shared` (NIP с контрольной суммой проверяется до отправки, принимает пробелы и дефисы); после отправки — «Zgłoszenie … wysłane» и ссылка на `/org`, где организация ждёт активации.
- `/admin/orgs` (суперадмин) — фильтр статуса в адресе (`PENDING` по умолчанию, «Wszystkie»), старые заявки первыми; «Aktywuj» / «Aktywuj ponownie» сразу, «Zablokuj» — со вторым подтверждением (блокировка останавливает продажу и закрывает страницы организации). `AdminNav` — общая навигация суперадмина над `/admin/orgs` и `/admin/claims`; иконка шапки ведёт, как раньше, на `/admin/claims`.
- `/org/:orgId/members` — форма приглашения (email, роль; после отправки — «Zaproszenie wysłane na …», адрес очищается), «Zaproszenia oczekujące» (роль, срок или «link wygasł», «Wyślij ponownie» — новое письмо заменяет ссылку, «Anuluj»), карточки членов: имя, email, «(Ty)» у себя, с какого дня, роли чекбоксами и «Zapisz role» (без изменений или без ролей — недоступна), «Usuń z organizacji» со вторым подтверждением. `LAST_ORG_ADMIN` и прочие отказы — переведённый `ApiErrorAlert` на карточке. Отказ API на список членов (`ORG_SCOPE_VIOLATION`, `FORBIDDEN`) — ошибка без форм. Изменения ролей перезапрашивают и `/me/orgs`: свои роли меняют разделы `/org`.
- `/invitations/accept?token=` (`RequireAuth`: гость входит и возвращается со ссылкой) — показывает, от имени какого адреса будет принято; приглашение принимается **только кнопкой** «Przyjmij zaproszenie» (предпросмотр ссылки почтовым клиентом или префетч не должны его использовать). Итог — «Dołączyłeś do organizacji … jako …», подсказка для роли и ссылка на `/org`; `INVITATION_EMAIL_MISMATCH` — ещё и совет войти в аккаунт с адресом из письма. Без `token` — ошибка без кнопки.
- `/org/:orgId/waters` — подключённые водоёмы (`GET /orgs/:orgId/waters`), от 9 — фильтр по названию без учёта регистра и диакритики (`shared/lib/search.ts`, «zegrzynski» находит «Zegrzyński»); без водоёмов — ссылка на заявку. `/org/:orgId/waters/:waterId` — данные из `GET /orgs/:orgId/waters/:id` (`no-store`, путь вне кэша Service Worker), а не из публичной карточки, которую SW отдаёт stale-while-revalidate: иначе после перезагрузки форма показала бы старые значения и вернула их на сервер (ревью T-23). Форма «Sezon» и «Opis łowiska» (`waterProfileSchema`, пустое поле — `null`) отправляет только изменённые поля; ответ любой правки (текст, фото, удаление фото) заменяет карточку формы, публичная перезапрашивается; фото — превью, `FileField` (тип и 5 МБ проверяются до отправки, окончательно — API по содержимому), «Zapisz zdjęcie», «Usuń zdjęcie»; ссылка на карточку. Отказ API (чужой водоём → 404) — `ApiErrorAlert`.
- Карточка водоёма (`/waters/:id`): фото над статусом (`<img>` по `GET /waters/:id/photo?v=<photoVersion>` — публичное, без токена), карточка «Sezon» и «Opis», внизу «Źródło danych: …, stan na <importedAt>» (у предложения рыбака — только источник).
- Service Worker: фото водоёмов — отдельный кэш `water-photos` (CacheFirst, 10 файлов, `purgeOnQuotaError` — фото до 5 МБ делят квоту с офлайн-уловами и уходят первыми; новое фото — новый адрес), а не `catalog-api` JSON-каталога.
- `/org/:orgId/permits` — `status` (Wszystkie / Aktywne / Zaplanowane / Wygasłe / Unieważnione), номер (поиск по кнопке) и `page` в адресе; смена фильтра возвращает на первую страницу; прежняя страница остаётся на экране, пока грузится следующая. Карточка: номер (Plex Mono), статус, владелец («Konto usunięte» у анонимизированного), тип, срок, цена, дата покупки, у аннулированного — «Data unieważnienia» и причина. «Unieważnij» только у `SCHEDULED`/`ACTIVE` (`isRevocable` из `shared`): форма на месте карточки, фокус на её заголовок, обязательная причина (`revokePermitSchema`), пояснение, что это необратимо и что возврат делается вне сервиса; «Anuluj» возвращает фокус на кнопку. После аннулирования над списком — «Zezwolenie … unieważnione.» (`role="status"`, фокус на нём: под фильтром «Aktywne» строка уходит из списка). Страница за концом списка (после аннулирования, старая ссылка) переходит на последнюю; пустой результат с фильтром — «Żadne zezwolenie nie pasuje do filtra.». Лимиты в подсказках — из констант `shared`.
- `/me/permits/:id` аннулированного разрешения (T-23, решение пользователя): над деталями — «Zezwolenie unieważnione przez organizację <дата>», причина и подсказка обратиться к организации за возвратом; QR и PDF нет, как у любого недействительного. Данные приходят и в офлайн-пакет устройства.
- Форма типа разрешения (T-12, пункт на потом): от 9 водоёмов — «Szukaj łowiska» (тот же фильтр; Enter в поле не отправляет форму) и «Zaznaczono X z Y»; фильтр только сужает показанный список, выбранные вне фильтра водоёмы остаются выбранными.

## Статистика (T-24)

- `/org` — у админа ссылка «Statystyki i eksport połowów» (`/org/:orgId/stats`).
- Период — в адресе (`?from=&to=`, текущий сезон — без параметров); неверный период в адресе молча заменяется сезоном (как `?season=` протоколов). Форма «Od» / «Do» — `statsRangeFormSchema` из `shared`, неверная дата — под своим полем, ошибка окна — под «Do»; пределы в тексте ошибки — из констант (`STATS_RANGE_MAX_DAYS`, `CATCH_SEASONS`); форма пересоздаётся при смене адреса (`key`), поэтому «назад» в браузере возвращает и поля.
- Карточки «Sprzedaż zezwoleń» и «Połowy»: числа (Plex Mono), под ними графики; при нуле — фраза вместо пустых графиков. Подсказка о возврате денег — только если есть аннулированные.
- Графики — без библиотеки (решение пользователя): CSS-столбцы и полосы на токенах дизайн-системы (`features/reports/components`). Каждый график — `<figure>` со списком: строка читается как подпись и значение, сам столбец `aria-hidden`; у столбца месяца — скрытая подпись «październik 2026: 4 zezwolenia, 100,00 zł». Под столбцами на телефоне — буква месяца (`month: 'narrow'`: 13 сокращений не помещаются в 375 px), от 640 px — сокращение и число над столбцом (на телефоне столбец ~20 px, сотни не помещаются). Точные числа и выручка по месяцам — в раскрываемой таблице «Pokaż miesiące w tabeli» (`<details>`), чтобы зрячий видел то же, что слышит скринридер (ревью T-24). Длина полосы — доля от максимума, ненулевое значение — не меньше 2 %.
- Виды — по `GET /species` на языке интерфейса, по числу убыв., при равенстве по алфавиту языка; пока словарь грузится, график видов не рисуется (иначе на мгновение все строки — «Gatunek spoza słownika»).
- «Pobierz plik CSV» — blob с токеном (`saveFile`), имя `polowy-<from>-<to>.csv` — период на экране.

## Проверка QR и протоколы (T-19)

- `/verify/:token` открыт всем (без `RequireAuth`): камера телефона открывает его из QR. Запрос ждёт восстановления сессии (`status !== 'restoring'`), ключ запроса включает статус сессии — после входа или выхода на странице ответ запрашивается снова. Расширенную часть решает API; на клиенте нет копии правил доступа. Без перезапроса при возврате на вкладку (инспектор уходит в камеру с недописанным протоколом) и `gcTime: 0`: ответ с данными владельца не остаётся в кэше после ухода со страницы и не достаётся следующему пользователю того же телефона. Неудачный перезапрос (нет сети) не убирает проверку и форму — над ними предупреждение «данные с HH:MM»; без данных — H1 «Sprawdzenie zezwolenia» и ошибка.
- Вердикт — `VerdictBanner` (заливка Success/Danger на всю ширину на телефоне, иконка 56 px, H1 «Zezwolenie ważne / nieważne»); у недействительного — причина по статусу (`SCHEDULED` — с какой даты, `EXPIRED`, `REVOKED` …) или «код неверный, подделан или истёк». Под ним — карточка: тип и статус, организация, срок, инициалы, водоёмы.
- Гость видит «Zaloguj się jako strażnik» (`/login` с `state.from`, после входа — обратно на проверку); вошедший без права — пояснение, что больше видят только инспекторы и админы организации-владельца.
- Инспектор и админ организации: «Dane do kontroli» (имя, фамилия, год рождения — сверить с документом, номер разрешения Plex Mono), «Połowy dzisiaj» — `CatchSummary` (вид, «Zabrana / Wypuszczona» и время, длина и вес, водоём, статус, причины отказа; общий с `CatchRow` реестра) и пометка, что видны только уже отправленные уловы. Форма протокола: результат — `SegmentedToggle` «Bez zastrzeżeń / Naruszenie» без значения по умолчанию, «Uwagi» до 2000 знаков, «Dodaj moją lokalizację» (`LocationField` из `shared/ui`, общий с формой улова), проверка — `inspectionFormSchema` из `shared`. Пока определяется позиция, «Zapisz protokół» недоступна — иначе протокол ушёл бы без запрошенной позиции. После сохранения форма заменяется подтверждением «Protokół zapisany o …», фокус — на нём.
- `/org/:orgId/inspections` (`RequireAuth`, ссылка «Protokoły kontroli» у админа в `/org`): сезон (`?season=`, последние 5 лет; в API уходит всегда, и текущий — год на экране, а не год сервера), карточки — время, результат (иконка + текст), номер и тип разрешения, владелец, инспектор, заметки. Отказ API (`FORBIDDEN` у инспектора) — переведённый `ApiErrorAlert`. Инспектору в `/org` — подсказка, что проверка начинается со сканирования QR.
