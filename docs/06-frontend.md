# 06. Frontend и PWA

Одно SPA для всех ролей. Офлайн нужен только рыбаку (запись улова, показ QR).

## Библиотеки

| Задача | Библиотека |
| --- | --- |
| Маршрутизация | React Router (data router) |
| Серверное состояние | TanStack Query |
| Формы | React Hook Form + Zod (схемы из `packages/shared`) |

## Каталог (T-09)

- `/` — карта и список под ней (`features/catalog`). Фильтры `region`, `type`, `status`, `q` хранятся в URL (ссылкой можно поделиться, работает «назад»); неизвестное значение в URL игнорируется.
- Без поиска карта запрашивает только свою видимую область (`bbox`, округление до 5 знаков); первый запрос уходит, когда карта сообщила реальные границы. Поиск по названию идёт по всему каталогу и приближает карту к результатам (после их прихода, не к прежним данным). «Wróć do mapy» возвращает по истории — с прежними фильтрами.
- Список под картой — доступная альтернатива маркерам, рисует не больше 100 записей; при `truncated` — подсказка «приблизьте карту» (в режиме поиска — «уточните название»).
- Маркер подключённого водоёма — заливка, «только реестр» — кольцо (не только цвет); статус текстом — в попапе и списке. Селекты фильтров на телефоне свёрнуты в «Filtry», чтобы карта была на первом экране.
- Страница отправляет `no-referrer` (`index.html`), а политика тайлов OSM требует Referer: у `TileLayer` `referrerPolicy="origin"` — только origin.
- Ссылка `externalInfoUrl` из импортированных данных показывается, только если это http(s).

## Офлайн

Таблицы Dexie:

| Таблица | Содержимое |
| --- | --- |
| `permits` | Активные и будущие разрешения (платформенные и внешние) + `qrToken` |
| `rules` | Эффективные правила по `permitId` (из `/offline-bundle`) |
| `species`, `waters` | Справочники для формы улова (водоёмы — только из разрешений) |
| `catchQueue` | Уловы: `clientId`, данные, `status: PENDING_SYNC / ACCEPTED / REJECTED`, `violations` |

Поток:

1. После оплаты и при каждом открытии онлайн — обновить `permits`/`rules` из `/offline-bundle`.
2. Форма улова вызывает `validateCatch` из `packages/shared` и сразу показывает нарушения.
3. Запись → `catchQueue` со статусом `PENDING_SYNC`.
4. Синхронизация: при событии `online`, при открытии приложения и по кнопке «Синхронизировать» — пакетами по 50 на `/catches/sync`.
5. Ответ обновляет статусы; `REJECTED` показываются с переведённой причиной.

Background Sync API не используется: его нет в Safari/iOS.

Workbox: app shell и статика — precache; `/api/v1/waters`, `/species` — StaleWhileRevalidate; остальное API — NetworkOnly (данные кэшируются в Dexie, а не в Service Worker). Тайлы карты — CacheFirst с лимитом 500 записей.

## API-клиент

- `pnpm gen:api`: API собирается и без БД и `.env` выгружает OpenAPI-документ (`apps/api/dist-openapi/openapi.json`, отдельно от `dist`, чтобы не мешать `nest start --watch`), `openapi-typescript` делает из него `src/shared/api/schema.d.ts`. Файл не коммитится; корневые `pnpm lint` и `pnpm typecheck` генерируют его сами.
- Клиент — `openapi-fetch`, пути с префиксом `/api/v1`, тот же origin: в dev Vite проксирует `/api` на `localhost:3000`, в prod — Caddy.
- Запросы идут только через `request()` внутри TanStack Query: он возвращает `data` или бросает `ApiError` с `code`. Компонент показывает `t(errorMessageKey(error))` (`ApiErrorAlert`).
- Кроме кодов API (`ErrorCode`) у клиента два своих: `NETWORK_ERROR` — ответа нет или прокси вернул 502/503/504 без тела API; `UNKNOWN_ERROR` — ответ не в формате `{ code }` или код неизвестен клиенту.
- Повторы: ответы 4xx не повторяются, сеть и 5xx — до двух раз.

## i18n

- Языки `pl` (по умолчанию), `en`, `ru`; файлы `src/shared/i18n/locales/{lng}/{ns}.json`. `ns` — фича; при загрузке файлы сливаются в одно пространство i18next под именем фичи, поэтому ключ — `home.page.title`, а не `home:page.title`. Ключи проверяет компилятор по ресурсам `pl`.
- Язык выбирается переключателем в шапке и запоминается в `localStorage` (`lowisko.locale`); определения по языку браузера нет. После входа (T-07) язык будет браться из профиля.
- Никаких строк в JSX — только `t('catch.form.length')`. Ключи — `feature.component.element`.
- Ошибки API переводятся по `code`: `t('errors.' + code)`.
- До этапа локализации допустимо заполнять только `pl`; пропущенные ключи в `en`/`ru` подхватывает fallback на `pl`.
- Даты и числа — `Intl` с локалью пользователя, часовой пояс `Europe/Warsaw`.

## UI-принципы

Цвета, типографика, отступы и компоненты — в `10-design-system.md`.

- Mobile-first: основной сценарий — телефон на берегу, одной рукой, на солнце. Крупные цели нажатия (≥ 44 px), высокий контраст.
- Форма улова ≤ 3 шагов (NFR-06): последние вид и водоём подставляются по умолчанию.
- QR — на весь экран, с подсказкой увеличить яркость и номером разрешения текстом.
