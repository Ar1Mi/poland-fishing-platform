# 07. Безопасность и RODO

## Угрозы и меры

| Угроза | Мера | Где |
| --- | --- | --- |
| Кража токена | Access JWT 15 мин в памяти (не localStorage); refresh 7 дней в cookie `httpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`; ротация, повторное использование отзывает семью. Остаточный риск: выданный access-токен действует до 15 мин после выхода или сброса пароля (не хранится на сервере) | AuthModule |
| Перебор паролей, нагрузка, спам | `@nestjs/throttler`: login 5/мин на IP+email; все публичные auth-маршруты, кроме refresh, — 20/мин на IP (каждый запрос может стоить хеша argon2 64 МиБ или письма); forgot-password — 3/ч на email (нельзя засыпать ящик письмами или бесконечно аннулировать ссылку жертвы); reset-password проверяет токен до хеширования; argon2id | AuthModule |
| Перечисление email | Одинаковый ответ на forgot-password для существующих и несуществующих адресов (токен и письмо создаются без ожидания, чтобы не выдать адрес временем ответа); login для несуществующего email сверяет пароль с фиктивным хешем. Принятый компромисс: регистрация отвечает `EMAIL_TAKEN` — понятность для пользователя важнее; перебор адресов через неё ограничен лимитом 20/мин на IP | AuthModule |
| Захват сессии после смены пароля | Сброс пароля отзывает все refresh-токены пользователя; ротация и отзыв токенов одного пользователя идут последовательно (advisory-lock транзакции), поэтому refresh в момент сброса не оставляет рабочего токена | AuthModule |
| Подделка QR | JWS Ed25519 (`jose`), payload `{ sub: permitId, exp }`; приватный ключ только на сервере (env); проверка подписи **и** текущего статуса в БД | PermitsModule, InspectionsModule |
| Скриншот чужого QR | Инспектор видит имя и год рождения, сверяет с документом | InspectionsModule |
| Утечка данных через публичную проверку | Публично — только действительность, тип, организация, срок, водоёмы и инициалы; имя, год рождения, номер и уловы — только `INSPECTOR`/`ORG_ADMIN` `ACTIVE`-организации-владельца. Ответ `Cache-Control: no-store` (зависит от токена). Поддельный, истёкший токен и неизвестное разрешение неотличимы. Присланный неверный access-токен — 401, а не гостевой ответ. Уловы — только этого разрешения за сегодня, не со всех водоёмов, и без координат. Токен из пути не пишется в лог запросов (T-19) | InspectionsModule |
| Подделка оплаты | Статус `PAID` только по уведомлению P24 с верной подписью **и** успешным `transaction/verify`; сумма сверяется с `Payment.amountGrosze` (иначе 400 `PAYMENT_AMOUNT_MISMATCH`, платёж остаётся `PENDING`); идемпотентность по `sessionId`: уведомление для платежа не в `PENDING` ничего не меняет и не подтверждается. Возврат браузера на `/payment/return` статус не меняет — страница только опрашивает API | PermitsModule (`permits/payments`) |
| Оплата «фейком» в рабочей среде | `POST /payments/fake/:sessionId/complete` отвечает 404, если `PAYMENTS_PROVIDER` не `fake`, а `POST /payments/p24/notification` — если не `p24` (иначе фейковый адаптер принял бы неподписанное тело); при `NODE_ENV=production` API с `fake` не стартует (проверка окружения, T-14) | PermitsModule (`permits/payments`) |
| Поддельное уведомление P24 | `POST /payments/p24/notification` публичный: подлинность доказывают контрольная сумма SHA-384 с ключом CRC (сравнение за постоянное время), наши `merchantId`/`posId`, валюта `PLN` и последующий `transaction/verify`. Иначе 400 `VALIDATION_FAILED`, в лог — только причина, без тела. Фильтр по IP-адресам P24 (рекомендация документации P24) не применяется — принятый риск (T-14): за туннелем или прокси адрес источника недостоверен, а без CRC-ключа подделать сумму нельзя | PermitsModule (`permits/payments`) |
| Открытый редирект со страницы фейковой оплаты | `returnUrl` из адреса страницы выполняется только как путь этого же приложения (`safeReturnPath`; путь с `//` в начале — тоже на главную), иначе — на главную | web |
| «Заморозка» нового типа разрешения | Принятый риск (T-13): брошенная оплата (`CANCELLED`) фиксирует срок, льготу и водоёмы типа и запрещает его удаление, поэтому любой рыбак может так закрепить условия нового типа. Ущерб — администратор создаёт новый тип; лимит покупок на пользователя — кандидат для T-28 | PermitsModule |
| Общий пароль демо-аккаунтов | `SEED_DEMO=true` (T-20) создаёт 7 аккаунтов, в том числе суперадмина, с одним паролем из `SEED_DEMO_PASSWORD`: в репозитории его нет, без него seed не стартует, при `NODE_ENV=production` — не короче 16 символов. Повторный seed отзывает refresh-токены и одноразовые ссылки демо-аккаунтов, как смена пароля, поэтому смена `SEED_DEMO_PASSWORD` обрывает выданные сессии (access-токен — до 15 мин). Вход ограничен throttler, сброс пароля по почте невозможен (домен `.test`). Демо-организации ищутся по фиксированному id, а не по публичному NIP: заявка с NIP из репозитория не будет переименована и активирована seed, он остановится с ошибкой. Остаточный риск: все, кто знает пароль, — суперадмин публичного демо; пароль задаётся только на время защиты, демо не хранит реальных данных | `prisma/seed-demo.ts` |
| Доступ к чужой организации (IDOR) | `OrgScopeGuard` на всех `/orgs/:orgId/*`; сервисы фильтруют по `organizationId`; тест на каждый маршрут | OrganizationsModule |
| Доступ к чужим уловам/разрешениям | Запросы `/me/*` всегда фильтруют по `userId` из токена, не из параметров | все |
| XSS | React-экранирование; запрет `dangerouslySetInnerHTML`; CSP через `helmet` | web, api |
| CSRF | Refresh-cookie `SameSite=Strict`; остальное — Bearer-токен | AuthModule |
| SQL-инъекции | Prisma; `$queryRaw` только с tagged template | все |
| Загрузка вредных файлов | Лимит 5 МБ, проверка типа по сигнатуре (`file-type`) и белый список (документ claim — PDF/JPEG/PNG/WebP), случайные имена, ключ вне корня хранилища отклоняется, отдача с `Content-Disposition: attachment`, `nosniff` и `Cache-Control: no-store`; документы claim скачивает только суперадмин; срок хранения документов — решение T-26 (RODO) | StorageService |
| Секреты | Только env; `.env` в `.gitignore`; `.env.example` без значений | — |
| Цепочка поставок | `pnpm install --frozen-lockfile`; скрипты установки только для разрешённых пакетов (`allowBuilds`); свежие релизы задерживает политика минимального возраста pnpm; CI — триггер `pull_request` (не `pull_request_target`), токен `contents: read`, без сохранения в `.git` | `pnpm-workspace.yaml`, `.github/workflows/ci.yml` |

## RODO

- **Минимизация:** номер karty wędkarskiej необязателен; дата рождения нужна только для льгот (BR-08).
- **Основание и согласие:** чекбокс при регистрации со ссылкой на политику конфиденциальности (страница-шаблон).
- **Доступ:** `GET /me/export` — JSON со всеми данными пользователя.
- **Удаление:** `DELETE /me` — персональные поля обнуляются/заменяются, `deletedAt` выставлен, уловы остаются обезличенными (для статистики организаций), разрешения сохраняются с маскированным владельцем.
- **Координаты улова** видит только владелец; организация видит водоём, но не точку.
- **AuditLog** фиксирует действия админов: аннулирование, решения по claim (T-11), создание, изменение и удаление типов разрешений — в том числе цены (T-12), изменение правил, блокировки. Запись делается в транзакции самого действия: изменение без записи в журнале (и наоборот) невозможно.
