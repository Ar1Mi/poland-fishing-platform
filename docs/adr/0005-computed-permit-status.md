# ADR-0005: Вычисляемые статусы разрешения

- **Статус:** Принято
- **Дата:** 2026-10-06
- **Связано:** FR-09, BR-01

## Контекст

Разрешение проходит состояния PENDING_PAYMENT → PAID → (SCHEDULED → ACTIVE → EXPIRED), может быть CANCELLED или REVOKED. Часть переходов зависит только от времени.

## Варианты

1. **Хранить все статусы, менять cron-задачей** — данные расходятся с датами, если cron не сработал; лишняя инфраструктура.
2. **Хранить только событийные статусы, временные вычислять** — всегда согласовано с датами.

## Решение

В БД — `PENDING_PAYMENT / PAID / CANCELLED / REVOKED`. `SCHEDULED / ACTIVE / EXPIRED` вычисляет функция `effectivePermitStatus(permit, now)` в `packages/shared`. Даты сравниваются по варшавскому календарному дню.

## Последствия

- Нет cron для смены статусов; cron остаётся только для отмены неоплаченных (> 30 мин) и email-напоминаний.
- Фильтр «активные» в SQL строится по датам, а не по полю статуса.
